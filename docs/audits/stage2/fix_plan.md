## Implemented in this audit

- **A1 (P0):** missing territory is unknown without explicit worldwide evidence, regardless of source provenance. Scraped offers with known countries honor local/VPN/out-of-reach status; only explicit `territorial_scope="worldwide"` grants global reach. The original A1 regressions and this follow-up regression failed before their fixes and pass afterward.
- **A2 (P1):** Watchmode coordinator reservation is not charged again by the client for the initial attempt; direct calls and retries still reserve per outbound attempt. Nested contexts cannot restore consumed credits. Regressions failed before the fix and pass after it.
- **A3 (P1):** queue `CHECKED` state no longer becomes definitive global unavailability when offers are empty. The title-source absence classifier remains responsible for a real negative. Cross-country prior success plus current failure regression passes.
- **A4 (P2):** detail source state is passed into the shared resolver, matching watchlist report pending/check status.
- **A1 follow-up (P0):** a known country now remains country-scoped despite scraper provenance. `territorial_scope="worldwide"` survives country filters and ranking only when explicit; blank country without that scope remains unknown. Prime/detail and v2 expose the same locality/accessibility.
- **A8 (P0):** `vpn_enabled=False` now blocks foreign VPN reach even if candidate regions are saved. Existing reach tests now explicitly enable VPN when exercising VPN regions.

Focused PostgreSQL regressions were run after recording the baseline failures. A5/A6/A7 remain follow-up work; no code edits have been made for them.
