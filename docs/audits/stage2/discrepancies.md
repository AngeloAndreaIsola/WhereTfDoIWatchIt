## Reproduction and evidence limits

The Watchmode reservation, refresh-state aggregation, empty-result resolver, and freshness helper were executed offline using their actual function bodies with in-memory stubs (no imports, DB, or network). The three initial failing regressions and post-fix focused Django tests ran against the disposable PostgreSQL test database. There were zero external HTTP/API calls and zero provider quota consumed.

The sample CSV contains 31 public-title candidates × four target markets (NL, IT, JP, CA) = 124 title-country cases. It is explicitly a synthetic/public cohort, not a watchlist snapshot. Source, timestamp, provider, offer, entitlement, language, freshness and verdict fields are unknown for every row; no independent title page was queried. All 124 outcomes are `UNVERIFIED`; title/ID pairings are cohort seeds and were not independently refreshed in this audit.

The old `docs/qa/release54/h1-accuracy-audit.md` is historical and refers to a pre-merge SHA. Its fuzzy-entitlement and unknown-language findings do **not** reproduce in this baseline: `UserAccess._match` uses exact canonical slugs (`tracker/services/access.py:282-288`), the safe alias table distinguishes Prime add-ons and Viaplay Sports (`:128-250`), and `score_offer` returns `None` for absent language metadata (`tracker/services/score.py:164-168`). Frontend `OfferLocality` and `OfferRow` expose `unknown` as “Territory unknown” rather than silently omitting locality.
