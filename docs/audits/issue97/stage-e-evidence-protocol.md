## Contemporaneous window

Approve an absolute half-open 30-minute UTC slot per typed title before capture. A comparison qualifies only when the first-party capture and index observation are in that title's slot and their combined observation span is **at most 10 minutes**, including clock uncertainty. An application comparison also includes the current local response capture and its contributing observations in that same span. The slot makes scheduling and audit boundaries reproducible. The smaller span limits exposure to changes in catalogues, promotions and availability while allowing serial requests, pacing and local replay. It is a proposed comparison tolerance, with no assumed guarantee that a listing was constant during the span.

1. Measure UTC start and completion of each relevant request or local read. Record the synchronization check, clock uncertainty of at most five seconds per host and the monotonic elapsed time. Use the original successful source response observation and the provider response capture, preserving request bounds. For a timestamped underlying assertion use its event time as well. Require the UTC bounds, expanded by recorded uncertainty, to fit inside the approved slot. Compute the span from the earliest expanded start to the latest expanded end. An unknown original observation time, unordered timestamps, unverifiable clock or failed response leaves the row ineligible.
2. Record comparable response age separately from request time. Reject known stale documents and evidence whose underlying assertion or verifiable cached origin predates the slot. Record relevant freshness metadata and whether origin is attested or only directly observed at fetch. Use original source timestamps for the application. Fetch time, import time, replay time and application read time each describe separate events. A fresh app response can carry only historical offers. Those rows stay `last_known`.
3. Use `needs_recheck` if reliable evidence straddles a stated start, end, price or promotion change, or if equally scoped signals conflict within the window. Record the reason without widening the window or substituting a historical row. An out-of-window or stopped capture remains in the attempt ledger. Any new capture requires a separately approved slot and budget.

## Adjudication and denominators

For each named index, use one row per distinct frozen `(media_type, tmdb_id, market, provider_slug, offer_class)` pair. Group reviews by batch, class, source and eligibility. Score only pairs passing identity, market, source independence, scope and time gates with both verdicts binary. Explicit absences count only at the reviewed scope.

| Index claim | Independent `yes` | Independent `no` | Independent `unknown` |
| --- | --- | --- | --- |
| `yes` | TP | FP | Unresolved positive claim |
| `no` | FN | TN | Unresolved negative claim |
| `unknown` | Abstention, record any retrieval miss separately | Abstention | Unresolved |

| Metric | Denominator and interpretation |
| --- | --- |
| Agreement and conflict counts | `TP + TN` and `FP + FN` over the independently adjudicated pair set. Publish zero adjudicated pairs when no cells are supported and mark outcome counts unclassified. |
| Agreement/accuracy and conflict rates | `(TP + TN) / N` and `(FP + FN) / N`, with `N = TP + FP + FN + TN`. |
| Precision | `TP / (TP + FP)` among eligible, verified positive index claims. Report the number of unresolved positive claims separately. |
| Recall | `TP / (TP + FN)` among independently positive pairs receiving a valid binary index claim. Publish abstentions among all eligible independent positives separately. |
| False-positive rate | `FP / (FP + TN)` among independently negative pairs receiving a valid binary index claim. Requires verified first-party negatives. |
| False-negative rate | `FN / (FN + TP)` among independently positive pairs receiving a valid binary index claim. FN requires an explicit current negative index assertion. |
| Display retrieval | Displayed pairs divided by the independently positive pairs eligible for the named display and with a completed, correctly scoped read. Report omitted pairs and unresolved display reads separately. |
| Price agreement | Equal-price pairs divided by all pairs with comparable rent/buy prices. Report mismatches and unknown-price pairs. Availability counts remain separate. |

Report each rate as `UNDEFINED` if its denominator is zero or cannot be established, and show its numerator and denominator when available. A rate on the binary adjudicated subset is conditional. In particular, recall of the full independent-positive panel is undefined if any positive pair has an unresolved or abstaining index claim. A preselected, positive-heavy or otherwise incomplete panel supports sample-conditional rates only. Report planned pairs, attempted/completed observations, eligible pairs, scored pairs, independent positives and negatives, unknowns, `needs_recheck`, missing/unmapped or excluded reasons, and stale/same-source evidence by count alongside the rates. Report confidence limits only under a justified sampling or statistical design. All current Stage E rates are `UNDEFINED`.
